# Silex native compiler experiment

This repository explores a native Silex compiler whose internal model does not
depend on generated C or C++.

The current bootstrap composes typed Silex modules and source packages into one
program. A package is consumed by identity, without a library path or linker
configuration:

```sx
use Math.Operations

func calculate() int {
    return Operations.add(20, 22)
}

func main() {
    calculate()
}
```

It lexes and parses the source, resolves and checks names and types, and lowers
the program to a typed IR. The same IR can be executed by the reference
interpreter or compiled directly to an ad-hoc-signed Mach-O executable for
Apple Silicon. The native path emits ARM64 instructions and the executable
container itself: it generates no C/C++ and invokes no external assembler or
linker.

## Try it

```sh
cd Toolchain
zig build test
zig build run -- run ../Examples/Packages/Main.sx --emit-ir
zig build run -- compile ../Examples/Packages/Main.sx -o ../packages-example
../packages-example
```

The interpreter and native ARM64 test harness both verify `calculate() == 42`.
The generated executable runs directly on macOS and exits with status
`0`. With `--emit-ir`, the interpretation command prints the typed operations,
including:

```text
func @Main.calculate() -> int {
entry:
    %0:int = const 20
    %1:int = const 22
    %2:int = call @Math.Operations.add(%0, %1)
    return %2
}
```

## Repository layout

```text
Docs/           language and architecture contracts
Examples/       executable Silex source files
Toolchain/      autonomous Zig bootstrap project
  Sources/      compiler implementation
```

Zig is the implementation language of the bootstrap compiler. It is not an
intermediate representation, runtime dependency, or ABI for compiled Silex
programs. The native backend is experimental, currently supports only
`macos-arm64`, and does not promise a stable ABI or stable generated bytes.

After `zig build`, add `Toolchain/zig-out/bin` to `PATH` during development to
invoke the public CLI as `silex run <source.sx>` or
`silex compile <source.sx> -o <executable>`.

Local packages are canonical sibling directories such as `Math/`, containing
`Package.json` and `Module/`. Installed packages live under
`~/.silex/packages/Name@MAJOR.MINOR.PATCH/`. Manifests declare dependencies as
exact (`=1.4.1`) or caret (`^1.4.0`) constraints; they never declare paths,
native symbols, or linkage options.
